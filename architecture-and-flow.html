Key Point: Firebase = Auth Only

Firebase handles only Google Sign-In and JWT token issuance. All user profile data (name, email, role, avatar) and meeting data is stored in MongoDB. The backend verifies the Firebase JWT, extracts the uid, and uses it to look up the user in MongoDB.

Role-Based Access Admin vs User

Admin ADMIN

  • View all meetings across every user in the organization
  • Manage users — view list, change roles (user ↔ admin), deactivate accounts
  • Delete meetings — remove any meeting record
  • View analytics — org-wide stats (total meetings, active users, action item completion rates)
  • Reassign action items — assign tasks from any meeting to any user
  • Export data — bulk export meetings as CSV/PDF

Normal User USER

  • View own meetings — only meetings they participated in or created
  • Capture meetings — use the Chrome extension to record transcripts
  • View AI summaries — read summary, MOM, action items for their meetings
  • Update action items — change status of their own assigned tasks
  • Profile management — update their own display name, avatar
  • Search & filter — search within their own meeting history

Role Assignment Logic

  • First user to sign up is automatically assigned admin role
  • All subsequent users default to user role
  • Admins can promote/demote other users via the dashboard
  • Role is stored in MongoDB (not in Firebase custom claims) for simplicity

End-to-End User Flows Step by Step

Flow A — First-Time Sign Up

1

User visits web app

Opens https://app.axythic.com → sees login page with "Sign in with Google" button.

2

Google OAuth

Firebase SDK opens Google popup → user selects their Google account → Firebase returns user object with uid, email, displayName, photoURL.

3

JWT sent to backend

Frontend calls getIdToken() → stores JWT in memory (not localStorage) → sends with every GraphQL request as Authorization: Bearer <token>.

4

Backend creates user in MongoDB

Auth middleware verifies JWT → finds no existing user → creates new document in users collection with role: "user" (or "admin" if first user). Returns user data.

5

Dashboard loads

Web app queries me → gets role → renders appropriate dashboard (admin or user view). First visit shows empty state with prompt to install Chrome extension.

Flow B — Capturing a Meeting

1

User joins Google Meet

Chrome extension detects the Google Meet URL → injects content script → caption observer starts watching for captions.

2

Live capture begins

User clicks "Start Capture" in the extension popup or the injected panel → background service worker starts accumulating transcript segments with speaker names and timestamps.

3

Meeting ends → User clicks "Stop"

Extension gathers all segments, formats into full transcript string, collects participant names.

4

Extension sends data to backend

Gets Firebase JWT from the logged-in user → sends createMeeting GraphQL mutation with transcript, title, participants, duration. JWT in Authorization header.

5

Backend processes with AI

Receives transcript → calls OpenAI GPT-4o → generates summary, MOM, and action items → saves complete meeting document to MongoDB.

6

User views results in dashboard

Web app shows new meeting in the list → user clicks to see AI-generated summary, minutes of meeting, and assigned action items with status tracking.

Flow C — Admin Managing Users

1

Admin opens Users panel

Sidebar shows "Users" nav item (admin only) → queries allUsers → displays table with name, email, role, last login, status.

2

Admin changes a user's role

Clicks role dropdown → selects "Admin" or "User" → fires updateUserRole mutation → backend checks requester is admin → updates MongoDB → UI reflects change.

3

Admin views all meetings

Admin dashboard shows all meetings across the org → can filter by user, date range, search keywords. Can delete any meeting.

Extension Authentication Critical

How the Chrome Extension Gets a Firebase JWT

  • Option used: chrome.identity API — The extension uses chrome.identity.getAuthToken() to get a Google OAuth token, then exchanges it with Firebase using signInWithCredential(GoogleAuthProvider.credential(null, token)).
  • Once signed in, the extension calls getIdToken() on the Firebase user to get a JWT.
  • This JWT is sent with every GraphQL request to the backend.
  • The token auto-refreshes (Firebase SDK handles this) — valid for 1 hour.
